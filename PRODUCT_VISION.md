# Manga Studio — Product Vision

## 1. Product

Manga Studio is a creative platform for writers and artists to create original stories, manga, characters, scenes and visual worlds.

The platform combines:

* Free-form writing
* Story organization
* AI creative assistance
* Character development
* Scene planning
* Visual generation
* Manga creation
* Publishing
* Community discovery and ratings

The fundamental principle is:

> The creator owns the story. AI assists the creator.

AI is never the unquestioned author.

---

# 2. Vision

Manga Studio should feel like a personal creative studio rather than a form-based story generator.

A creator should be able to open a new project and immediately start writing.

They should not be required to define:

* Genre
* World
* Characters
* Art style
* Plot
* Story structure

before writing.

These things can emerge naturally from the creator's work.

The creator can define them manually, allow AI to discover them, or use a mixture of both.

---

# 3. Core philosophy

## Creator-first

The creator has final authority over:

* Story
* Characters
* World
* Timeline
* Dialogue
* Visual identity
* Canon
* Publishing

AI suggestions are proposals.

The creator decides whether they are accepted.

## Free-form

The creator should not be forced into rigid forms.

The system should support:

* Long-form writing
* Notes
* Ideas
* Drafts
* Character descriptions
* Dialogue
* Scene descriptions
* Images
* References
* Outlines
* Timelines

The creator can organize their work however they want.

## Progressive structure

The application should gradually understand the project.

For example, if the creator writes:

"Aki is seventeen and his brother disappeared when he was ten."

The system may identify:

Character:
Aki

Age:
17

Relationship:
Brother

Important event:
Brother disappeared

But the extracted information remains editable and must not override the creator's original writing.

---

# 4. AI philosophy

AI should behave like a combination of:

* Writing assistant
* Story editor
* Brainstorming partner
* Continuity checker
* Visual director
* Research assistant
* Production assistant

The AI should not constantly interrupt the creator.

AI should be available when requested and may provide passive suggestions when useful.

Examples:

* Improve selected text
* Continue a scene
* Brainstorm possibilities
* Generate alternative dialogue
* Suggest plot directions
* Detect continuity problems
* Explain existing story elements
* Create character concepts
* Create scene concepts
* Plan manga panels
* Generate visual references

---

# 5. Writer control

AI-generated content must never silently modify creator content.

Every AI modification must support:

* Accept
* Reject
* Edit
* Regenerate
* Compare

When appropriate, AI should show what changed.

Example:

Creator text:

"Aki entered the room."

AI proposal:

"Aki slowly entered the abandoned room, unsure of what waited beyond the darkness."

The creator chooses whether to use it.

---

# 6. Canon

The project needs a concept of canon.

Canon represents information the creator has established as authoritative.

AI suggestions are not automatically canon.

Possible states:

* CANON
* DRAFT
* IDEA
* AI_SUGGESTION
* UNKNOWN
* CONTRADICTED
* ARCHIVED

The creator can change the status.

---

# 7. Stories are allowed to evolve

Creators must be able to change their minds.

They can:

* Rename characters
* Change ages
* Rewrite history
* Delete scenes
* Rewrite chapters
* Change relationships
* Change the ending
* Retcon previous events
* Create alternate versions

The system should preserve history rather than preventing changes.

Continuity warnings should inform the creator rather than block them.

---

# 8. Studio experience

The Studio is the primary creation environment.

It should contain:

* Project navigation
* Writing editor
* Chapters
* Characters
* Locations
* Timeline
* Notes
* AI assistant
* Visual assets
* Scene builder
* Manga editor

The creator should be able to move between these areas without losing context.

---

# 9. Writing experience

The writing editor is the heart of the application.

It should support:

* Rich text
* Markdown-like shortcuts where appropriate
* Headings
* Dialogue
* Notes
* Selection-based AI actions
* Autosave
* Undo/redo
* Version history
* Search
* Comments/annotations

AI actions should be available contextually.

---

# 10. Character experience

Characters are persistent entities.

A character may appear in many chapters and scenes.

The creator can define characters manually or allow the system to extract them from writing.

A character may contain:

* Name
* Aliases
* Description
* Personality
* History
* Relationships
* Abilities
* Equipment
* Clothing
* Visual references
* Expressions
* Poses
* Notes
* Canon information

Characters can evolve over time.

Historical versions must be preserved.

---

# 11. Visual creation

The platform should support:

* Character concept generation
* Character reference sheets
* Locations
* Objects
* Scenes
* Action scenes
* Fight scenes
* Manga panels
* Manga pages
* Covers

Visual generation should use project context and character identity.

The creator should be able to regenerate individual components rather than regenerating an entire page.

---

# 12. Scene creation

A written scene can optionally be transformed into a visual scene.

The AI may propose:

* Characters
* Location
* Action
* Camera
* Composition
* Lighting
* Emotion
* Environment
* Panel sequence

The creator can modify these before generating images.

---

# 13. Manga creation

A story can eventually become a manga.

The production flow is:

Writing
→ Scene
→ Visual direction
→ Panel planning
→ Panel generation
→ Page composition
→ Dialogue
→ Final page

The creator can manually edit the result.

---

# 14. Publishing

Creators can publish completed or ongoing stories.

Publishing should support:

* Draft
* Private
* Unlisted
* Public
* Scheduled release

A story may contain:

* Cover
* Description
* Chapters
* Tags
* Creator information
* Ratings
* Comments

---

# 15. Reader platform

Readers should be able to:

* Discover stories
* Search
* Read
* Like
* Rate
* Comment
* Bookmark
* Follow creators
* Follow stories
* Track reading progress

The reader experience should be visually separate from the complex Studio.

Readers should not feel like they are using an authoring tool.

---

# 16. Community

The platform should encourage discovery rather than popularity alone.

Potential discovery categories:

* Trending
* New
* Rising
* Highly rated
* Following
* Recommended

Recommendation systems should eventually consider:

* Reading behavior
* Likes
* Ratings
* Genres/tags
* Similar stories
* Creator relationships

---

# 17. Ratings

Initial rating system should remain simple.

Readers can provide:

* Rating
* Like
* Comment

More sophisticated rating dimensions can be introduced later based on user behavior.

---

# 18. Creator profiles

Creator profiles should contain:

* Avatar
* Name
* Biography
* Published stories
* Followers
* Likes
* Statistics

Creators should control which information is public.

---

# 19. UX principles

The interface should be:

* Clean
* Modern
* Fast
* Intuitive
* Responsive
* Keyboard-friendly
* Accessible

Avoid excessive configuration.

Do not make every concept a separate form.

Progressive disclosure should be preferred.

Simple actions should remain simple.

Advanced functionality can appear when needed.

---

# 20. MVP

The first MVP should focus on creation rather than social networking or image generation.

MVP features:

1. Authentication
2. Projects
3. Free-form writing
4. Chapters
5. Autosave
6. Version history
7. Characters
8. Basic project knowledge
9. AI assistant
10. AI writing assistance
11. AI brainstorming
12. Basic continuity detection

Do not build the complete social network or advanced image generation in the first milestone.

---

# 21. Long-term vision

The long-term product should become a complete creative ecosystem:

Creator
→ Story
→ Characters
→ World
→ Scenes
→ Visuals
→ Manga
→ Publication
→ Readers
→ Community

Manga Studio should allow a creator to go from a single idea to a complete published manga without losing creative control.

---

# 22. Non-goals

Manga Studio is not intended to:

* Automatically write entire stories without creator involvement
* Replace the creator
* Force stories into predefined templates
* Automatically modify canon
* Lock creators into one AI provider
* Require users to understand AI prompting
* Require users to understand visual generation technology

The technology should be complex underneath.

The creative experience should be simple.
